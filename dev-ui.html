Auto generation help

Quick start

Enable auto for a value key and write a prompt on the auto tab. Use preview to inspect the resolved prompt for the selected piece. Use fill empty to generate only when the merged value is still blank, or the row auto button on the piece tab to overwrite.

Prompt levels

  • default — project-wide fallback prompts (saved in dev.json)
  • collection — per-collection flavour (saved in collections/<pad2>.json)

Insert reference

[collection.name]Collection display name

[piece.displayName]List label
[examples.description]Inline peer descriptions (optional)

Peer examples

When enabled in collection auto settings, other pieces' values are appended so the model matches established flavour. Each peer is formatted with the peer example template (same insert syntax as prompts). Peers are separated by ---. Omit property lines your project does not use.

Tips

  • Generate name before description
  • Collection brief is shared context for all prompts
  • Use collection-level prompts for per-collection tone; keep default minimal

Platform

Auto generation requires the Construct² Electron app (npm start). The xAI key is stored in app userData, not the project repo.

Collection auto settings help

    
Collection brief

    
Shared creative context for every auto prompt in this collection. Referenced as [collection.brief] in prompt and peer templates.

    
Peer examples

    
When Include peer examples is on, other pieces in this collection are appended to the LLM message so new generations match established tone. Each peer is formatted with the peer example template (same insert syntax as prompts). Peers are separated by ---.

    
Which pieces count as peers?

    
    
      
  • Single-field generate (preview, piece-tab auto, fill empty): a piece is included only if the field being generated is non-empty on that piece (e.g. generating description → peers need a description).
    • 
      
  • Auto fill (batch, piece list): a piece is included if any key listed in Peer example keys is non-empty (comma-separated, OR logic).
    • 
    

    
Peer example keys do not control which fields appear in the block — that is the template. They only gate batch auto fill eligibility.

    
Settings

    
    
      
  • Max peers — cap how many earlier pieces are shown (by piece number, excluding the current piece).
    • 
      
  • Peer example template — one block per peer; use inserts below. Omit lines your project does not need.
    •
